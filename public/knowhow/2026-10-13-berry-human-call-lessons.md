# 베리와 사람의 3분 통화 — 듣기·침묵·종료·전달에서 배운 것

2026-10-13 · 음성 AI/자동화 · T-261001-003

세탁소 상담 봇과 말을 주고받은 뒤, 전화 AI 베리를 사람과 시험했다. 2026년 10월 13일 저녁, 사용자의 승인을 받아 기존 아이폰 회선으로 한 번 전화했다. 양쪽 소리를 합친 녹음은 약 3분 7초다.

첫 반응은 목소리가 잘 들린다는 것이었다. 대화가 이어지자 다른 문제가 드러났다. 상대가 말하는 중에 답했고, 조용히 기다려 달라는 요청에도 말을 이어 갔다. 통화를 마치려는 의사도 매끄럽게 처리하지 못했다. 통화 뒤에는 요약과 녹음의 자동 전달이 빠졌다.

이 글은 **익명화한 대화 흐름과 개발 과정**을 남긴다. 대화 내용은 자동 받아쓰기와 베리 재생 기록을 대조해 뜻을 요약했다. 원문 인용이나 음성으로 교정한 전문은 아니다. 상대 이름·연락처·원본 녹음은 공개하지 않는다.

## 1. 실제 대화에서 드러난 문제

| 장면 | 상대의 반응·요청 요약 | 베리의 반응 요약 | 여기서 배운 점 |
| --- | --- | --- | --- |
| 첫 인사 | 목소리가 잘 들리고 속도도 괜찮다고 답했다. | 들린다는 답에 호응했다. | 소리 전달은 확인했지만 대화 품질은 아직 확인하지 못했다. |
| 응원 전달 | 앞으로도 개발을 열심히 하라는 뜻을 전했다. | 응원을 전달하겠다고 답했다. | 짧고 분명한 내용은 주고받았다. |
| 말 끊기 지적 | 아직 말하는 중이니 끊지 말라고 여러 번 요청했다. | 사과하거나 계속 말해 달라는 답을 반복했다. | 듣겠다는 답을 말하는 동안에도 상대의 차례를 빼앗을 수 있다. |
| 듣기 상태 확인 | 아직 말이 끝나지 않았는데 다 들었다고 하는 이유를 물었다. | 듣고 있으니 편하게 말하라고 답했다. | 정중한 문장만으로 잘못된 말끝 판정을 복구하지 못한다. |
| 5초 침묵 요청 | 지금부터 약 5초 동안 조용히 기다려 달라고 했다. | 조용히 듣겠다고 말한 뒤 다시 반응했다. | 침묵은 답변 문구와 별도로 실행하고 측정할 동작이다. |
| 내용 불일치 지적 | 말을 하지 않았는데 베리가 발언이 있었던 것처럼 반응한다고 지적했다. | 계속 말해 달라는 답을 이어 갔다. | 받아쓰기 오류와 늦게 나온 답을 함께 확인해야 한다. |
| 통화 종료 요청 | 대화를 그만하고 먼저 끊어 달라는 뜻을 여러 번 전했다. | 마무리를 안내하다가 다시 말해 달라고 답하기도 했다. | 종료 의사를 받은 뒤에는 일반 대화 답변이 끼어들지 않아야 한다. |

후반의 불편은 상대가 직접 지적했다. 다만 받아쓰기·답변 대기·재생 중 어느 단계가 각 끼어들기를 일으켰는지는 모두 확정하지 못했다. 자동 받아쓰기에는 비언어 동작처럼 보이는 표기도 있었다. 그런 표기를 실제 행동이나 종료 동의로 해석하지 않았다.

## 2. 모델 응답 시간과 통화 응답 시간을 구분한다

이번에 확인한 수치는 다음과 같다.

| 확인 항목 | 결과 | 해석 범위 |
| --- | --- | --- |
| 양쪽 소리를 합친 녹음 길이 | 약 186.76초 | 약 3분 7초 분량의 녹음이다. 연결 타이머와 같은 값이라는 뜻은 아니다. |
| 상대 말끝 → 베리 답 소리 시작 | 측정한 본응답 23건에서 3.474~19.763초 | 로컬 녹음에서 구한 간격이다. 상대 귀에 도착한 시각은 측정하지 않았다. |
| 3초 이내 답 소리 목표 | 미달 | 짧은 모델 응답 시간만으로 이 목표를 통과했다고 볼 수 없다. |
| 통화 종료 뒤 상태 | 실제 통화 비활성 확인 | 베리가 종료 버튼을 누른 기록은 없다. |

대화 중에는 이미 오래된 요청에 대한 답이 나올 수 있다. 상대는 다음 말을 하는데 베리는 앞의 말에 사과하거나 호응한다. 이번 기록에서도 이런 엇박자가 관찰됐다. 다만 각 답이 늦어진 내부 원인을 하나로 단정하지 않는다.

이 시험에서 얻은 설계 기준은 세 가지다. 상대가 새로 말하면 아직 재생하지 않은 답의 유효성을 다시 판단한다. 침묵 요청은 대기 상태와 시간으로 다룬다. 종료 의사를 받으면 일반 답변 대기를 정리한다. **이 기준을 글로 정리한 것과 실제 대화 제어를 고친 것은 별개다. 이번 전달 누락 수정만으로 말 끊기가 해결됐다고 기록하지 않는다.**

## 3. 끊겠다는 말과 실제 종료를 함께 확인한다

이번 통화에 적용한 조건은 상대가 먼저 끊거나, 베리가 종료를 물은 뒤 상대의 명확한 동의를 받는 것이었다. 시간에 따른 종료 질문은 5분 뒤로 설정했다. 강제 시간 종료는 켜지 않았다.

대화 도중 종료 질문이 실제로 재생됐지만, 이후 발화까지 반영한 유효한 동의 확인 기록은 남지 않았다. 베리는 종료 버튼을 누르지 않았다. 베리가 말하던 중 통화 연결이 사라졌고, 별도 확인에서 통화가 끝난 것을 확인했다. 상대가 직접 버튼을 눌렀는지 통신이 끊겼는지는 구분하지 못했다.

제어 프로그램은 이 상황을 통화를 열어 둔 오류처럼 분류했다. **종료 분류 기록과 실제 통화 상태가 어긋났다.** 따라서 오류 코드 하나로 통화가 계속 중이라고 단정하면 안 된다.

통화가 끝난 뒤 사용자는 더 넉넉한 시간 제한을 승인했다. 이후 기본값을 **연결 후 5분에 종료 질문, 명확한 동의가 있으면 조기 종료, 동의가 없으면 10분에 마무리 안내 후 종료**로 바꿨다. 이 설정은 로컬 검사와 검토를 통과했다. 이번 약 3분 통화에서 10분 종료를 시험한 것은 아니다.

## 4. 통화가 끝나도 기록 전달까지 확인해야 한다

사용자가 통화 요약과 녹음이 카카오톡으로 오지 않는다고 지적했다. 확인 결과, 발신 명령에서 통화 후 전달 설정인 `--post-call-config`를 빠뜨렸다. 그 실행에는 자동 전달 이벤트가 하나도 없었다.

사용자가 허용한 본인 대상 전달 범위를 실행 담당자가 이어받지 못한 것이 직접 원인이다. 프로그램도 전달 설정을 선택 사항으로 처리했다. 설정이 없어도 발신을 시작했고, 완료 검사도 통화와 녹음에 집중했다. **실행자의 누락을 발신 전 검사와 완료 판정이 잡지 못했다.**

전달을 복구하는 과정에서는 다른 제한도 드러났다. 녹음 검사의 상한은 180초였는데 이번 파일은 약 187초였다. 파일 복사에는 고정 30초 제한이 있었다. 이 제한들은 최초 옵션 누락과 별개의 장애였다.

파일 복사를 복구한 뒤 요약과 녹음 전송을 각각 한 번 시도했다. 두 전송의 확인 결과는 모두 불명확했다. 수신과 재생을 확인하지 못했으므로 전달 성공으로 기록하지 않았다. 중복 전송을 막기 위해 재발송하지 않았다.

## 5. 전달 누락 재발을 막기 위해 바꾼 것

사용자 승인 후 다음 네 가지를 구현했다.

| 변경 | 막으려는 실패 | 확인한 범위 |
| --- | --- | --- |
| 본인 전달 설정을 기본 프로필에 연결 | 발신할 때 전달 옵션을 잊는 실수 | 설정 누락·불일치·전달 경로 준비 실패를 발신 전에 차단하는 검사 |
| 요약과 녹음의 전송 확인 기록을 각각 요구 | 녹음 파일만 생겼는데 전체 완료로 처리 | 같은 통화의 실제 종료·녹음 확정·요약 준비·두 전송 확인을 모두 대조 |
| 긴 통화에 맞춰 녹음·파일 복사 한도 조정 | 10분 통화 정책과 180초 녹음 제한의 충돌 | 녹음 한도 660초, 파일 크기별 복사 시간, 실제 약 187초 녹음과 합성 600초 녹음 검사 |
| 전송 전 실패와 전송 결과 불명확을 구분 | 확인 오류 뒤 같은 메시지 중복 발송 | 전송 의도와 항목별 결과 보존, 불명확한 전송의 자동 재시도 금지 |

관련 로컬 검사 138개가 통과했다. 기본 전달 프로필과 기존 녹음 실행 경로도 수정본에 연결했다. 실제 녹음 원본과 기존 전송 기록이 바뀌지 않은 것을 확인했다.

수정 후 새 통화나 카카오톡 재전송은 하지 않았다. 따라서 이 검사는 다음 실통화의 자동 전달 성공이나 사용자의 녹음 재생을 증명하지 않는다. 이번 통화의 지연과 말 끊기도 별도로 남아 있다.

## 6. 이 통화에서 남긴 검증 기준

전화 AI는 소리가 들리는지부터 확인한다. 그다음 상대의 말을 끝까지 듣는지 확인한다. 침묵 요청과 종료 요청은 실제 동작으로 확인한다. 통화가 끝나면 요약과 녹음의 전달 결과를 각각 확인한다.

2026년 10월 13일 기록 기준으로, 짧은 내용의 왕복과 양쪽 녹음은 확인했다. 자연스러운 대화 차례, 3초 응답 목표, 새 종료 정책의 실통화 동작, 통화 기록의 수신·재생은 확인 과제로 남았다. 전달 누락 방지 코드를 고쳤다는 사실로 이 항목들을 함께 완료 처리하지 않는다.

## 픽업
- 처음에는 코드를 고치지 말고 코드베이스에 질문만 하라고 한다. Anthropic 기술 신입 온보딩은 이 방식으로 2~3주에서 2~3일이 됐다고 말한다. 코드를 원격 인덱스에 올리거나 생성 모델 학습에 쓰지 않고, 설치 직후 기다림 없이 바로 묻는다고 한다.
- 깃 히스토리는 절차를 길게 적을 필요가 없다. "깃 히스토리를 봐"라고만 하면, 인자 15개인 함수가 왜 그렇게 생겼는지, 누가 넣었는지, 커밋이 가리키는 이슈까지 요약한다고 한다. 시스템 프롬프트에 깃 절차가 있어서가 아니라 모델이 깃을 쓰기 때문이라고 말한다. 매주 월요일 "이번 주 내가 뭘 냈지"도 같은 방식이다.
- 큰 기능은 코드를 쓰기 전에 아이디어를 내고 계획을 보여 승인을 받으라고 한다. 플랜 모드나 특수 도구는 필요 없고, "코드 쓰기 전에 계획을 짜라"고 말하면 된다고 한다. "커밋 푸시"라고만 해도 브랜치를 만들고, 기존 깃 로그를 보고 커밋 형식을 맞춘 뒤 풀 리퀘스트를 연다고 한다.
- 결과를 확인할 수단을 주면 스스로 반복한다고 한다. 유닛 테스트, Puppeteer 스크린샷, iOS 시뮬레이터가 그 예다. 목업만 주고 한 번에 시키면 괜찮은 수준이고, 두세 번 고치게 하면 거의 맞게 나온다고 말한다.
- CLAUDE.md는 세션을 시작한 폴더 루트에 두면 매 세션 첫 턴에 자동으로 읽힌다. 팀과 공유할 파일은 깃에 넣고, 개인용은 넣지 말라고 한다. 자주 쓰는 명령, MCP 도구, 구조 결정, 중요한 파일을 짧게 적는다. 길어지면 컨텍스트만 먹고 쓸모가 줄어든다고 한다. 하위 폴더의 파일은 그 폴더에서 일할 때만 읽힌다.
- `#` 뒤에 기억할 말을 적으면 CLAUDE.md에 들어간다고 한다. `/memory`로 회사 정책, 개인 메모리, 프로젝트 파일, 하위 폴더 파일이 어떻게 읽히는지 본다. Shift+Tab은 편집만 자동 수락하고 배시 명령은 여전히 승인이 필요하다. `!`로 친 로컬 명령과 출력은 다음 턴 컨텍스트에 들어간다. Esc는 세션을 망치지 않고 멈추고, Esc 두 번은 이전 기록으로 돌아간다. 끝난 세션은 `--resume` 또는 `--continue`로 다시 연다.
- 많이 쓰는 사람은 같은 저장소를 여러 개 받아 두거나 git worktree로 격리해서 Claude Code를 여러 개 동시에 돌린다고 한다. `claude -p`는 프롬프트를 넣고 JSON을 받는 유닉스 도구이고, CI와 장애 대응 파이프라인에서 쓴다고 말한다.

## 용어
- **CLAUDE.md** [지식 · 컨텍스트 자산]: 프로젝트 루트에 두면 매 세션 시작 때 자동으로 읽히는 지시 파일. 팀 공유본은 깃에 넣고, 개인용은 넣지 않는다.
- **코드베이스 Q&A** [하니스 · 패턴]: 코드를 고치기 전에 저장소에 질문만 해서, 모델이 어디까지 혼자 하는지 감을 잡는 시작법.
- **MCP** [도구 통신 (MCP · CLI · API)]: 팀이 이미 쓰는 도구를 Claude Code가 대신 부르게 연결하는 방식. 설정 파일을 저장소에 넣으면 동료도 같은 도구를 쓰게 된다.
- **Puppeteer** [도구 통신 (MCP · CLI · API)]: 화면을 찍어 웹 UI 결과를 모델이 스스로 확인하게 하는 도구. Boris는 목업을 넣고 이 서버로 반복시킨다고 한다.
- **git worktree** [하니스 · 패턴]: 같은 저장소를 폴더를 나눠 동시에 여러 세션이 서로 파일을 건드리지 않게 하는 깃 기능.
- **claude -p** [도구 통신 (MCP · CLI · API)]: 프롬프트를 넣고 JSON을 돌려받는 Claude Code 명령. 파이프와 CI에 붙이는 유닉스 도구로 설명된다.
- **/memory** [지식 · 컨텍스트 자산]: 회사 정책, 개인 메모리, 프로젝트 CLAUDE.md, 하위 폴더 파일이 어떻게 읽히는지 보여주고 고치는 슬래시 명령.
- **Shift+Tab 자동 수락** [하니스 · 패턴]: 파일 편집은 매번 승인하지 않고, 배시 명령은 그대로 승인을 요구하는 모드.

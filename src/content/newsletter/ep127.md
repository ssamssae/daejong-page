## 이번 이야기

검사가 모두 통과하면 로고도 잘 만들어졌다고 말할 수 있을까요? 회사 로고에 들어가는 −β를 다시 생성하는 과정에서 이 질문이 남았습니다. 생성 기능이 작동하는지와 결과물의 글자가 읽히는지는 각각 확인해야 했습니다.

## 직접 겪은 일

로고 생성 지시의 충돌을 수정하고 고객 화면에서 다시 시도했습니다. API 회귀 검사 13개, UI 회귀 검사 7개와 빌드가 통과했습니다. 실제 시안 네 개도 생성해 PNG와 SVG, 비교 이미지와 압축 파일로 전달했습니다.

여기까지가 확인된 실행 결과입니다. 그런데 생성된 로고는 여전히 β의 가독성이 부족했습니다. 수정과 생성, 파일 전달까지 마쳤어도 글자가 잘 읽히는 결과에는 도달하지 못한 겁니다.

## 배운 점

이 사례에서 제가 얻는 교훈은 완료 기준에 결과물의 목적을 직접 넣어야 한다는 것입니다. 기술 검사는 생성 과정이 작동한다는 근거가 됩니다. 여기에 로고를 보는 사람이 기호를 알아볼 수 있는지까지 확인해야 디자인의 완성도를 이야기할 수 있습니다.

검사를 더 많이 붙이는 것만으로 해결될 문제는 아닐 수 있습니다. 무엇을 확인하는 검사인지가 먼저입니다. 이번에 남은 문제는 분명했습니다. β가 더 잘 읽혀야 했습니다.

## 독자에게

무언가를 만들고 있다면 완료 조건에 사용자가 얻어야 할 결과를 한 문장으로 적어보세요. 로고라면 ‘보는 사람이 의도한 기호를 알아볼 수 있다’처럼요. 그리고 실제 결과물을 놓고 그 문장이 충족되는지 확인해보면 좋겠습니다. 파일이 만들어졌다는 사실 다음에 무엇을 봐야 할지 선명해집니다.

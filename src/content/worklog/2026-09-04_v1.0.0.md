> 08:29, 강제 종료 뒤 되살아나던 Codex 중간보고의 라이브 검증을 끝냈다.
> 12:39, Cursor 브릿지가 Claude·Grok·Codex 브릿지와 같은 응답·상태 계약을 갖췄다.
> 20:39, 텔레그램에서 Cursor Grok 4.6까지 선택할 수 있게 됐다.

전날은 Cursor 화면을 잘못 읽는 문제를 고쳤다. 오늘은 브릿지 자체의 모양을 정리했다. 답이 두 줄에서 잘리고, 이미 전달한 작업이 재시작 뒤 다시 큐에 들어가고, 같은 사진이 세 번 붙고, 모델 선택은 터미널에서만 가능한 상태였다. 각각은 작은 결함이지만 폰에서 쓰면 하나의 경험으로 겹친다.

## 1. 두 줄짜리 답은 답이 아니었다

Cursor Telegram Bridge에는 폰 답변을 두 줄로 자르는 제한이 있었다. 긴 진행 보고가 “오늘 진행 상황 정리입니다. 완료.” 정도에서 끝났다. 텔레그램 전송부는 원래 긴 메시지를 나눠 보낼 수 있었으므로, 앞에서 잘라낼 이유가 없었다.

[#2132](https://github.com/ssamssae/claude-automations/pull/2132)는 두 줄 제한을 없애고 문단 구조를 보존했다. 추천답변은 모델이 `<추천답변>`으로 명시한 경우에만 별도 버튼으로 보냈다. 브릿지 재시작 뒤 작업을 회수할 때도 단순히 기록을 봤다는 사실이 아니라 **실제 전달 영수증**이 있는지를 기준으로 삼았다.

같은 PR에는 Cursor 입력창에 지시가 남아 있을 때 Space+Enter로 한 번 더 제출하는 경로도 들어갔다. 화면에 붙여넣은 것과 Cursor가 턴을 시작한 것은 다른 사건이기 때문이다.

## 2. 같은 사진이 세 번 들어간 이유

텔레그램 사진 하나가 Cursor에 세 번 붙은 일이 있었다. 첫 입력이 실패한 것이 아니었다. Cursor의 follow-up 목록에 `○` 항목으로 정상 대기 중이었는데, 브릿지가 이를 미제출로 판정해 작업을 실패 큐에 넣었다. 재시도할 때마다 같은 사진을 다시 붙였다.

[#2133](https://github.com/ssamssae/claude-automations/pull/2133)은 follow-up 목록에 같은 요청이 대기 중이면 제출 성공으로 인정했다. 재시도는 전달 실패를 복구하는 장치지만, 성공을 실패로 읽는 순간 중복을 만드는 장치가 된다.

## 3. 네 번째 브릿지도 같은 문법을 쓴다

[#2134](https://github.com/ssamssae/claude-automations/pull/2134)는 Cursor 브릿지를 Claude·Grok·Codex 브릿지와 같은 계약으로 맞췄다.

- 일반 답변과 복사용 명령, 추천답변을 같은 순서로 렌더링
- `/start`, `/ping`, `/status`의 응답 종류 통일
- 큐 처리 수와 오류, 워커 생존 상태를 같은 health 형식으로 기록
- 여러 스레드가 동시에 상태를 써도 파일이 반쪽 나지 않도록 원자적으로 교체

기능을 새로 많이 붙인 것보다, 네 브릿지가 같은 질문에 같은 모양으로 답하도록 만든 것이 핵심이다. 운영 도구는 기능 수보다 예측 가능성이 중요했다.

## 4. 모델 선택도 폰에서

저녁에는 Cursor의 `/model` 선택창을 텔레그램으로 옮겼다. 이전에는 폰에서 Cursor를 쓰다가 모델을 바꾸려면 직접 터미널로 가야 했다.

[#2135](https://github.com/ssamssae/claude-automations/pull/2135)는 `/model` 명령에 인라인 메뉴를 붙이고 현재 모델에 표시를 더했다. 버튼을 누르면 허용된 모델 이름만 Cursor 팔레트에 넣고, 상태줄에서 실제 전환 결과를 다시 읽어 알려준다. 터미널에서 직접 연 모델 선택창도 폰에 한 번만 나타난다.

처음 메뉴에는 Cursor Grok 4.5까지만 있었다. Hermes와 Vulcan의 실제 세션은 4.6을 쓰고 있어 현재 모델 표시가 비었다. [#2136](https://github.com/ssamssae/claude-automations/pull/2136)으로 Grok 4.6을 추가했다. 화면의 실제 값이 허용 목록보다 먼저 움직인 사례였다.

## 5. 중간보고 루프와 자기소개 한 장

아침에는 전날 main에 들어간 Codex 중간보고 수리를 라이브에서 닫았다. 관련 테스트 167개와 공개 브릿지 내보내기 테스트 79개를 통과했고, Hermes 브릿지를 다시 시작한 뒤 새 진행 내용이 없는 상태에서 빈 보고가 되살아나지 않는지 확인했다.

낮에는 AI 창업 스터디에서 쓸 자기소개 한 장을 만들었다. [kangdaejong.com](https://kangdaejong.com)의 공개 자료에서 제품 16개, 출시 앱 7개, 공개 도구 3개, 뉴스레터 111편을 추려 “작게 만들고, 오래 운영합니다”라는 한 문장 아래 배치했다. AI 자동화 줄에는 Codex·Claude·Grok과 함께 Cursor Bridge를 넣었다. 결과물과 재생성 코드는 [#55](https://github.com/ssamssae/kangdaejong-com/pull/55)에 열어 두었다.

## 6. 밀린 세 날짜를 닫는다

작업장 작업일지는 9월 1일에서 멈춰 있었다. 오늘 9월 2일, 3일, 4일 기록을 실제 main 커밋과 작업 상태에 맞춰 다시 썼다. 완료되지 않은 PR은 완료라고 쓰지 않았고, 공개 페이지에 필요 없는 내부 경로와 식별값은 덜어냈다.

오늘 main에 들어간 Cursor 브릿지 변경은 긴 답변, 전달 영수증 기반 복구, 중복 사진 차단, 공통 브릿지 계약, 모델 메뉴와 Grok 4.6 지원이다. 이제 폰에서 질문하고, 답을 끝까지 읽고, 필요한 문장을 복사하고, 모델을 고르는 흐름이 한 화면 안에 들어왔다.

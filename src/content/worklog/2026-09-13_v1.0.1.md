> 00:27, 시스템 문서와 헤더가 회사 홈과 같은 줄로 맞았다.
> 12:33, 뉴스레터 Ep.120이 홈페이지에 올랐다.
> 15:36, 한줄일기가 토스 미니앱 SDK3로 올라갔다.

자정부터 헤더를 맞추고, 낮에는 뉴스레터를 「쓰는 일」과 「올리는 일」로 나눴다. 오후에는 한줄일기가 토스 새 SDK를 타고, 초소는 실제 작업 신호를 다시 그리기 시작했다. 하루가 길었다.

## 1. 헤더가 다른 집 간판을 달고 있었다

자정 27분, 작업장 시스템 문서와 하위 페이지가 회사 공통 헤더로 통일됐다. [daejong-page PR #532](https://github.com/ssamssae/daejong-page/pull/532), 이어서 lab 현행화가 [PR #533](https://github.com/ssamssae/daejong-page/pull/533). 밤 10시 50분에는 스택 페이지를 이날 역할 기준으로 다시 썼다.

회사 홈에서는 뉴스레터를 새 창으로 열고, 작업장 하위 메뉴를 달았다. [kangdaejong-com PR #63](https://github.com/ssamssae/kangdaejong-com/pull/63). 밤 10시 31분, 작업장 메뉴에서 시스템을 실험실 위에 두었다.

인사이트도 같은 날 올라갔다. 저커버그 개인 AI 편과, AI 비용·ChatGPT Work 활용 편이 목록에 붙었다.

## 2. 뉴스레터는 쓰기 전에 올리면 안 된다

낮 12시 전후, 매일 뉴스레터를 예약 시각 전에 쓰게 하고, 작업일지처럼 생긴 원고는 발행하지 않게 막았다. 홈페이지 본문 확인과 Substack·네이버 로그인도 같은 묶음에서 고쳤다. Ep.120은 12시 33분에 홈페이지에 올랐다.

작성 스킬과 예약 발행기는 역할을 나눈다. 한 파일이 둘 다 하면, 초안이 곧 공개가 된다.

## 3. 토스 안의 일기를 새 바닥에 옮겼다

오후 3시 36분, [한줄일기](https://play.google.com/store/apps/details?id=com.daejongkang.hanjul) ([App Store](https://apps.apple.com/kr/app/id6764308678)) 가 Apps-in-Toss SDK3와 웹 플랫폼 호환 수정을 합쳤다. [hanjul PR #126](https://github.com/ssamssae/hanjul/pull/126)이다. 전날 설정 화면 정리에 이은 미니앱 바닥 교체다.

초소는 오후 내내 실제 작업 중/대기 신호를 다시 모았다. 긴 요청 본문이 잘리지 않게 하고, 손님용 공개 요약도 달았다. 카카오봇은 채팅 탭과 사진 후속 질문을 되살렸다.

> **배운 것** — 헤더·메뉴·미니앱 SDK는 본문보다 먼저 들킨다. 어제 얼굴을 바꿨으면, 오늘 남은 문은 같은 집 간판이어야 한다.

## 4. 그래서 뭐가 남았나

작업장과 회사 홈의 헤더는 맞춰졌고, 한줄일기 SDK3와 Ep.120은 공개됐다. 폰에서 주관식 답을 보내는 길은 밤 8시 49분에 코드로 들어갔고, 이튿날 실제 입력칸 인식으로 이어진다. 음성입력 독립 앱은 아직 합쳐지지 않았다.

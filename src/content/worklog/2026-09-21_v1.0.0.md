기록 범위는 9월 20일 21시부터 9월 21일 21시까지다. 9월 26일에 완료 근거를 다시 대조해, 작업 제목만 나열하던 본문을 고쳤다.

> 입타를 내려받아 설치할 수 있게 했다.
> 말한 문장을 다듬는 속도는 실제 응답으로 비교했다.

## 1. 말로 쓴 문장을 기다리는 시간을 줄였다

입타는 말한 내용을 글자로 받아 적고, 필요하면 문장을 다듬어 입력하는 도구다. 이번에는 문장을 다듬는 기능에서 실패하거나 오래 기다리는 문제를 다뤘다. 같은 문장을 처리해 보며 어느 부분에서 시간이 걸리는지 비교했다.

맥의 한 비교 환경에서는 문장 다듬기 평균 시간이 약 13.7초에서 12.1초로 줄었다. 모든 방식이 빨라진 것은 아니다. 개선이 확인되지 않은 방식은 기존 설정을 유지했다. 이 수치는 해당 환경의 비교 결과이며, 모든 컴퓨터에서 같은 속도를 보장한다는 뜻은 아니다.

## 2. 고친 내용을 설치 파일로 묶었다

입타 0.1.21의 맥용 설치 파일과 윈도용 실행 파일을 공개했다. 맥용 파일은 공증을 마쳤고, 공개된 파일이 검사한 파일과 같은지도 확인했다. 이후 맥 개선판 0.1.22를 작업용 컴퓨터 두 대에 설치하고 실제 문장 응답을 확인했다.

코드를 고치는 것과 사용자가 설치할 파일을 내놓는 것은 별개다. 이날은 설치 파일 공개까지 진행했지만, 윈도의 모든 실제 입력 상황을 확인한 것으로 묶지는 않았다. 받아쓰기부터 사용 중인 앱의 입력칸에 글이 들어가는 과정은 별도 확인이 필요한 부분으로 남겼다.

## 3. 내부 실험도 읽을 수 있는 사례로 남겼다

작업 자료를 미리 골라 AI가 읽을 양을 줄이는 방법을 홈페이지 노하우에 정리했다. 공개 목록과 본문이 열리는지, 모바일에서도 읽을 수 있는지 확인했다. 실험 결과를 남기는 목적은 도구 이름을 나열하는 데 있지 않았다. 어떤 자료를 먼저 걸러야 불필요한 처리를 줄일 수 있는지 설명하는 데 있었다.

## 4. 이날 끝난 것과 남은 것

완료한 범위는 입타 설치 파일 공개, 맥의 문장 다듬기 비교와 적용, 노하우 글 게시다. 윈도에서 실제로 말한 결과가 원하는 입력칸에 들어가는지와 사용자가 느끼는 대기 시간은 별도로 확인해야 했다.

> **배운 것** — 응답 속도, 설치 파일 공개, 실제 입력 성공은 각각 확인해야 한다. 하나가 끝났다고 나머지까지 끝난 것은 아니다.

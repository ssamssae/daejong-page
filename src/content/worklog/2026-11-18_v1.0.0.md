## 오늘 한눈에

전날 밤 9시부터 이날 밤 9시까지 133건의 작업 기록에 손댔습니다. 그중 취소 18건은 대부분 같은 일을 놀고 있던 다른 컴퓨터 일꾼에게 옮기거나 다른 작업에 합치면서 접은 것입니다. 가장 큰 일은 토스 앱 안에서 파는 천원 토정비결과 글쓰기 묶음 「글방」에 사주·타로·대표기도문·영어이름·축사 결제를 코드로 붙이는 작업이었습니다. 저녁까지 승인된 코드 작업이 모두 합쳐졌고, 클로드가 실제 아이폰17을 조작해 결제창을 열었다가 취소하는 데까지 확인한 결과 어긋난 곳이 없었습니다. 다만 결제 상품 등록과 토스 검토 요청이 남아 있어 새 상품 대부분은 아직 손님이 살 수 없습니다. 밤사이 11개 앱의 아이콘을 한 글자 모양으로 바꾸는 작업이 끝나 아침에 스토어 제출이 이어졌고, 홈페이지에서는 복붙 정리기를 종료 목록으로 옮겼습니다. 그 밖에 맥 화면 조작 도구의 검토 지적을 고쳤고, 작업 분배 규칙을 정비했고, 답이 없는 질문 카드를 보조 폰 알림과 전화로 알리는 장치를 만들었습니다.

## 천원 토정비결 새 상품

토스 앱 안에서 파는 천원 토정비결에 꿈해몽·궁합·사주·타로를 붙이는 일입니다. 코드를 합친 것과 실제 운영에 내보낸 것을 나눠 적습니다.
- 밤에 마무리한 세 건: 꿈해몽·궁합 풀이가 상품마다 맞는 AI 설정을 쓰도록 고쳤습니다(22:03). 홈에 「다른 풀이」 카드 자리도 만들었는데, 결제가 연결된 상품만 보이는 방식이라 그때는 0개여서 홈 화면은 그대로였습니다(22:28). 여러 상품 안내문과 처리방침 문장 초안도 합쳤습니다(22:59). 처리방침 원문 검토, 토스 검토, 회사 홈페이지 처리방침과 맞추기, 시행일 판단은 이 작업 범위 밖이라 윗단계 작업으로 넘겼습니다.
- 꿈해몽·궁합 결제 상품 번호: 토스 콘솔에 등록된 상품 번호를 서버 조회표와 설정에 넣었습니다. 처음 맡긴 일꾼에서 차례만 기다려서 다른 일꾼으로 옮긴 뒤 새벽 1시 6분에 합쳤습니다. 이것만으로 배포되거나 상품이 노출되지는 않습니다.
- 사주: 입춘·절기 기준으로 사주 네 기둥과 오행 분포를 계산하는 부분을 만들었습니다(09:38). 1900~2050년 모든 날짜를 따로 계산한 값과 맞춰 보니 어긋난 날이 없었고, 입춘 시각은 천문연구원 값과 몇 분 이내로 맞았습니다. 이어서 풀이 서버 모듈(10:05), 입력 화면과 서버 연결(11:19), 내 풀이 목록 표시·결제 상품 자리·처리방침 초안(11:43)을 합쳤습니다. 실제 AI 품질 평가는 금지된 범위라 돌리지 않았습니다. 입력 화면 첫 작업은 지시서에 앱 쪽 타입 파일이 빠져서 검수에서 막혔고, 접은 뒤 새 작업이 그 변경을 이어받아 끝냈습니다.
- 결제 연결: 서버가 상품별로 남은 풀이권 수를 알려 주고, 앱이 상품별 초안과 풀이를 부를 수 있게 했습니다(12:08, 첫 등록은 다른 일꾼으로 옮기면서 접음). 꿈해몽·궁합 입력 화면의 결제 단추를 실제 결제에 잇고, 개인정보가 저장되는 나라 안내 문구도 맞췄습니다(12:49).
- 타로: 서버 모듈(13:41), 카드를 초안 단계에서 서버가 뽑아 저장하는 입력 화면(14:10), 내 풀이 목록·결과 화면·결제 상품 자리·처리방침 초안(14:28)을 고칠 것 없이 합쳤습니다. 서버 모듈은 같은 저장소를 다른 작업이 쓰고 있어서 첫 등록이 거부됐고, 차례를 기다렸다가 들어갔습니다.
- 사주·타로 결제 단추: 두 입력 화면의 결제 단추도 결제 흐름에 이었습니다(16:05). 하지만 운영 서버에 두 상품의 결제 번호가 없어서 실제 단추는 계속 막혀 있습니다. 코드로는 팔 준비가 됐고, 결제 상품 등록·실제 AI 시험·처리방침 문장 확정·토스 검토 요청처럼 승인이 필요한 일만 남았습니다.
- 처리방침 시행일: 앱 안 처리방침을 2026년 11월 18일 시행으로 바꾸고 바뀐 내용을 한 줄 더했습니다. 회사 홈페이지 처리방침과 12개 절을 맞춰 보니 모두 같았습니다(15:42).
- 서버 새 판과 기기 확인: 16시 18분 대종님 승인을 받아 운영 서버를 새 판으로 올렸습니다. 운영 설정에는 토정·꿈해몽·궁합 결제 상품이 있고, 사주·타로는 비어 있으며, 값은 990원입니다. 가짜 결제로 컴퓨터에서 먼저 확인한 뒤 20시 9분에는 클로드가 실제 아이폰17을 원격으로 조작해 토스 앱 시험 주소에서 확인했습니다. 홈에는 꿈해몽·궁합 카드만 있었습니다. 사주·타로 주소로 들어가면 입력은 되지만 결제 단추가 흐리게 막히고 「아직 열리지 않았어요」가 떴습니다. 처리방침에는 11월 18일 시행이 보였습니다. 꿈해몽·궁합·토정은 결제창까지 연 뒤 취소해서 실제 결제는 0건이었고, 어긋난 곳은 없었습니다. 사람이 손님처럼 직접 써 본 확인은 아닙니다.
- 프로모션 손님 첫 화면(진행 중): 프로모션으로 들어와 구경만 한 손님 1,340명 중 입력 화면까지 간 사람이 6명뿐이었습니다. 그래서 10초 안에 무료로 한 번 써 볼 수 있게 첫 화면을 고치는 일입니다. 밤 11시 14분 첫이름 쪽 변경과 토정비결 띠 12칸 변경을 운영용 갈래에 합쳤습니다. 앞서 합친 홈 카드 변경과 한 줄이 겹쳤는데 둘 다 살려서 정리했습니다. 첫이름 미리보기 기능이 운영 서버에서 응답하는 것도 확인했습니다. 토정비결 새 판은 토스 검토 중이라 출시하지 않았고, 승인이 나면 출시한 뒤 프로모션을 다시 시작할지 승인 카드로 묻습니다.

## 글방 새 상품

글쓰기 상품 묶음에 「글방」이라는 이름을 붙이고, 자소서 첨삭 외에 축사·대표기도문·영어이름을 더하는 일입니다. 저녁 7시 18분까지 승인된 코드 작업은 모두 합쳐졌습니다. 배포와 결제 상품 등록은 하지 않았습니다.
- 홈 카드: 글쓰기 홈을 자소서·축사 두 카드로 바꿨습니다(밤 10시 17분, 한 번 고친 뒤 합침). 옛 홈을 설명하는 출시 문서를 고치는 일은 윗단계 작업으로 넘겼습니다.
- 이름과 로고: 확정 이름 「글방」과 로고 「글」을 넣었습니다(08:22).
- 처리방침의 축사 입력: 축사 편지를 쓸 때 받는 입력을 처리방침에 적었습니다(08:46). 대종님이 볼 점이 몇 가지 남았습니다. 바뀐 문장 전문은 토스 검토 전에 판단이 필요하고, 위탁·파기 절은 아직 첨삭만 가리킵니다. 축사 화면의 요약 문구도 처리방침과 다르고, 축사 완성 글을 보관하는 기능은 아직 없습니다.
- 콘솔 자료: 토스 콘솔 등록 글과 출시 전 점검 문서를 글방 기준으로 다시 썼습니다(08:41). 등록용 화면 사진도 다시 찍었습니다(09:42, 자소서 첨삭 2,900원·축사 편지 1,900원 카드). 축사 문단은 콘솔에 붙이기 전에 축사를 열지 말지에 맞춰 다듬어야 합니다.
- 축사 결제 연결: 다섯 단계를 차례로 합쳤습니다. 서버의 상품별 저장·지급(11:27), 상품별 보기 응답과 축사 결과 화면·내 글 목록(12:02), 축사 이용권과 축사용 AI로 초안·글 만들기(12:54), 살 수 있는 상품만 홈 카드로 보여 주는 앱 뼈대(13:36), 축사 입력 화면의 결제 단추(14:04)입니다. 내 글 목록 작업은 처음 맡긴 일꾼에서 옮기면서 한 번 접었습니다. 운영 데이터베이스 반영, 축사 결제 상품 번호 입력, 배포, 폰에서 실제 결제 확인은 아직입니다.
- 대표기도문: 대기 목록에서 꺼내 서버 모듈부터 합쳤습니다(11:00). 재물을 약속하거나 헌금을 권하는 표현을 금칙에 추가했고, 실제 AI 호출은 하지 않았습니다. 화면과 처리방침은 같은 파일을 건드리는 축사 결제 연결 뒤로 미뤘습니다. 오후에 입력·결과 화면과 홈 카드(16:23, 첫 검수에서 문장 하나의 말투를 고침), 처리방침·잠금 시험(16:39)을 합쳤습니다. 일꾼 자리가 차서 두 번 다른 일꾼으로 옮기며 옛 기록을 접었습니다. 마지막으로, 기도문 초안이 자소서 상품으로 잘못 저장되고 하루 이용 한도도 섞여 계산되던 문제를 고쳐 기도문으로 저장·계산되게 했습니다(19:11). 결제는 닫혀 있고, 홈 카드는 결제 상품 번호가 생겨야 보입니다. 기도 제목에 다른 사람 이름·병명·신앙 내용이 들어갈 수 있어서, 처리 근거와 동의 문구는 대종님 판단이 필요합니다.
- 영어이름: 따로 있던 영어이름 서비스를 글방으로 옮겼습니다. 서버 모듈(17:20), 입력·결과 화면(17:41, 표시 이름 「영어이름 짓기」), 처리방침·잠금 시험(17:57) 모두 고칠 것 없이 합쳐졌습니다. 결제는 닫혀 있고 홈 카드도 없습니다. 결정을 기다리는 일이 셋 있습니다. 「아이 이름」 용도에는 만 14세 미만 아이의 이름·성별이 들어갈 수 있어 처리 근거와 동의 문구를 더할지, 홈 소개 한 줄에 영어이름을 넣을지, 처리방침 위탁·파기 절을 영어이름까지 넓힐지입니다.
- 콘솔 자료 다시 맞추기: 축사 결제와 기도문 화면을 반영해 콘솔용 사진과 소개 글을 다시 맞췄습니다(17:35). 문서 속 코드 위치 인용 두 곳을 고친 뒤 합쳤습니다. 영어이름까지 반영해 처리방침 사진과 상품 줄도 한 번 더 맞췄습니다(19:18). 콘솔 소개 글 두 줄은 대종님이 정합니다.

## 앱 아이콘 한 글자 통일

- 전체 흐름(진행 중): 약먹자의 「약」처럼 앱마다 한 글자와 앱별 색으로 아이콘을 통일하는 일입니다. 새벽 2시 53분까지 11개 앱(노래찾기·우리 사이·집사리모컨·모여요·살아있음·메모요·나눠요·한줄일기·할일요·가계부·계산기알람)의 아이콘 교체가 모두 검수를 거쳐 코드에 합쳐졌습니다. 아침에 스토어를 보니 심사 중인 판이 없었고, 대종님이 이번 아이콘 출시를 한 번에 승인했습니다. 그래서 앱스토어 8개 앱 심사 제출, 플레이 7개 앱 출시 등록, 집사리모컨 테스트 배포 빌드 업로드까지 했습니다. 심사·검토 결과는 아직 나오지 않았습니다. 할일요는 새 판에 아직 덜 끝난 구글 드라이브 로그인 기능이 들어 있어서 내보내지 않고 멈췄습니다. 첫이름은 이번 범위 밖입니다.
- 모여요: 웹을 앱처럼 감싼 안드로이드 앱이라 손이 더 갔습니다. 버전을 올려 새로 빌드하고, 대종님 승인을 받아 갤럭시 S24에 시험판을 깔았습니다. 파란 바탕 「모」 아이콘, 주소창 없이 열리는 화면, 로그인 화면을 확인한 다음 플레이 정식 트랙에 올렸습니다. 구글 검토를 통과하면 바로 공개되는 설정입니다. 토스 미니앱 로고는 검토가 3~7영업일 걸리고 그동안 수정이 잠긴다는 안내가 떠서, 새 로고를 임시저장만 하고 검토는 요청하지 않았습니다. 지금 공개된 로고는 옛 지도 핀 그대로입니다.

- 승인 전화(지켜보는 중): 60분 동안 답이 없는 승인 카드를 보조 폰이 전화로 읽어 줍니다. 대종님이 말로 승인·거절하면 대신 눌러 주고, 위험도가 큰 승인은 빠집니다. 14시 24분에 합쳤습니다. 첫 실통화 시험은 전화를 걸기 직전에 대종님이 텔레그램에서 먼저 눌러 멈췄습니다. 15시~15시 4분 두 번째 시험에서는 텔레그램을 누르지 않은 채 통화로 「승인」을 받아 대신 누르는 데까지 성공했습니다. 처음부터 승인이라고 말해도 확인 질문에 카드 내용을 붙이도록 보완했습니다. 60분 단계가 브릿지에 실제로 올라간 뒤, 첫 실제 카드에서 다시 봅니다.
- 승인 앱 아이콘(진행 중): 아이폰·워치용 승인 앱 아이콘을 대종님이 「역시 1번이 낫다」고 해서, 앞서 확정한 3번 대신 1번으로 바꿔 합쳤습니다. 다른 컴퓨터에서 다시 설치하도록 넘겼고, 기기에 깔린 것은 아직 확인되지 않았습니다.

## 맥 화면 조작 도구

클로드가 맥 화면의 창을 읽고, 누르고, 글자를 넣는 도구를 다듬는 일입니다. 대종님이 마우스를 쓰는 중에도 커서를 뺏지 않는 것이 핵심입니다.
- 마지막 단계 시험(진행 중): 밤 9시에 앞선 검토 지적을 고치고, 커서를 뺏지 않는 방식을 기본으로 바꿨습니다. 실제 화면 시험에서 전체 흐름이 통과했습니다. 커서 위치와 맨 앞 앱이 시험 전후로 같았고, 기록에 입력한 글자가 남지 않았습니다. 스크롤 막대 값을 바꾸면 「됐다」고 답하면서 실제로는 안 움직이던 결함을 하나 더 찾아, 페이지 넘김 동작으로 바꿨습니다. 마우스를 직접 쓰는 경로는 대종님이 마우스를 쓰는 중이라 실제 화면 시험을 하지 않았습니다. 별도 검토 결과는 「고치면 합쳐도 된다」였습니다. 중대한 문제가 1개 나왔는데, 입력이 관찰한 창에 묶이지 않아 같은 앱의 다른 창에 글자가 들어갈 수 있다는 것이었습니다. 중요한 문제 7개와 사소한 문제 11개도 나왔습니다. 이를 세 묶음으로 나눠 맡겼고, 사소한 것은 처음 공개하기 전까지 고칩니다. 프로그램 등록, 텔레그램 「나에게」 메시지 보내고 지우기 시험, 스킬 연결은 아직입니다.
- 첫째 고침: 입력은 관찰한 창에만 넣고, 글을 쓰는 칸이 아니면 입력을 거부하게 했습니다. 밤 11시 5x분에 코드는 합쳤지만, 작업 장부를 닫는 관문이 Swift 시험을 증거로 읽지 못해서 종결이 막혔습니다. 관문을 우회하지 않고 대종님께 물었습니다.
- 관문 고치기: 대종님이 「추천대로 해 줘」라고 해서, 장부를 닫는 관문이 Swift 시험 파일을 증거로 인정하게 고쳤습니다. 첫 검수에서 한 번 보완해 08:29에 합쳤고, 바로 이어 첫째 고침을 08:30에 닫았습니다.
- 둘째 고침: 화면 요소를 알아보는 규칙을 하나로 합치고, 글자가 있는 가장 가까운 상위 요소를 기준으로 삼게 했습니다. 첫 계획이 종결 막힘으로 끝나면서 남아 있던 일을 같은 지시서로 다시 등록했습니다. 첫 검수에서 새 규칙이 옛 규칙보다 약해지는 경우를 직접 재현해 보완을 요구했고, 고친 뒤 09:32에 합쳤습니다.
- 셋째 고침: 네 가지를 고쳐 09:59에 합쳤습니다. 뒤에 있는 창을 누를 때 다른 것에 가려졌는지 확인하고, 「눌렸는지 모름」을 오류와 구분하고, 글자가 사라졌는지 제대로 판정하고, 잠금을 오래 쥐고 있지 않게 했습니다.
- 세 고침 모두 실제 화면에서 확인할 항목(열린 메뉴 항목 누르기, 뒤 창 클릭, 경고 창 등)은 마지막 단계 시험으로 넘겼습니다.

## 작업 분배와 자동화 정비

여러 컴퓨터의 AI 일꾼에게 일을 나누고 검수하는 체계를 손봤습니다.
- 텔레그램 현황판: 고정 현황 글을 1시간마다 새 글로 보내 새로 고정하고, 바로 앞 고정은 풀게 했습니다. 그 사이 5분마다 하는 갱신은 지금처럼 글을 고치고, 밤 10시~아침 7시에는 새 글 없이 고치기만 합니다. 밤 9시 37분에 코드를 합쳤습니다. 실제 텔레그램 보내기·고정은 시험 범위 밖이어서 첫 실가동은 다음 날 아침 7시였고, 그 결과는 이 기록에 없습니다.
- 15분 진행 알림: 밤 10시가 되면 멈추고 밤사이엔 켜지지 않던 시간 제한을 없앴습니다. 대종님이 알림이 왜 정해진 시간에 멈추냐고 물은 데서 시작했습니다. 이제는 맡긴 일이 없고 클로드도 일을 끝냈을 때만 멈춥니다. 네 컴퓨터에 반영했고, 밤 10시 30분 세 대에서 실제 알림이 나가는 것을 확인했습니다. 일이 없던 한 대는 켜지 않았습니다.
- 병목 검토: 다른 컴퓨터의 클로드가 읽기만 하는 방식으로 구조를 검토했습니다. 지난 24시간 검수 77건의 대기 시간은 중앙값 2.6분이었지만 최대 41분 기다린 경우도 있었습니다. 가장 큰 손실은 검수가 아니라, 한 자리에 일 7건을 몰아 2시간을 기다리게 한 배정이었습니다. 결론은 검수 자리는 검수만 하게 비우고, 검수 줄을 「검수 먼저·온 순서」로 고치고, 등록할 때 한 컴퓨터에 몰리지 않게 막자는 것이었습니다. 대종님은 그중 작은 규모의 안과 승인 대기 목록, 사용량 85% 알림을 승인했습니다.
- 검수 순서: 검수가 온 순서가 아니라 무작위 번호 순서로 나가서, 늦게 온 검수가 먼저 처리되던 문제를 고쳤습니다. 이제 검수를 먼저, 먼저 온 순서대로 내보냅니다(01:56).
- 등록 검사: 검수 전용 자리에 일반 작업을 맡기면 막습니다(이유를 적었을 때만 예외). 등록할 때 컴퓨터별로 쌓인 일 수를 보여 주고, 한쪽으로 몰리면 경고하거나 막습니다(02:33). 그 영향으로 교차 검토의 기본 검수 자리가 막히게 되어, 다른 자리를 지정해야 한다고 안내서에 적었습니다.
- 클로드 주간 사용량 85% 알림: 주간 사용량이 85%를 넘으면 초기화 주기마다 한 번 대종님께 알림 카드를 보내는 기능을 만들어 새벽 1시 30분에 합쳤습니다. 검수할 때 실제 알림은 보내지 않았고, 설치는 대종님 요청을 받은 뒤 하는 후속 작업으로 따로 등록했습니다. 그런데 오전 규칙 알림 기록에는 주간 알림 설치까지 끝났다고 적혀 있는 반면, 설치 후속 작업은 여전히 열려 있습니다. 그래서 실제 설치와 첫 판정 기록 확인까지 끝났는지는 확정할 수 없습니다.
- 새 규칙 알림: 새 규칙을 다른 세 컴퓨터의 클로드에게 알렸고 모두 받았습니다. 검수 전용 자리에는 일을 맡기지 않고, 컴퓨터별로 고르게 나누고, 승인 대기 목록을 쓰고, 검수 순서와 85% 알림을 따르는 내용입니다. 한 곳은 처음에 「열린 계획 없음」이라고 적었다가 이미 3건이 있다고 정정했습니다. 규칙 코드는 네 컴퓨터에 설치까지 끝났습니다(09:42).
- 다시 볼 날짜 경고: 결정을 기다리는 일의 다시 볼 날짜가 지나면, 담당 컴퓨터의 클로드가 장부를 쓰거나 현황을 볼 때 맨 위에 「내 몫 날짜 지남」을 띄우게 했습니다(08:59). 대종님께 묶어서 한 통 보내는 안은 뺐습니다. 하루 두 번 결정 대기 목록을 보내는 알림이 이미 있어서입니다.
- 일꾼 사용률 90% 목표와 승인 대기 목록(진행 중): 그록·커서를 주간 90%까지 쓰자는 목표를 위해 규칙을 정했습니다. 각 컴퓨터가 할 만한 일 후보를 모아 저녁에 대종님께 번호로 올리고, 고른 것만 대기 목록에 넣습니다. 아침에 대종님이 「제안대로」라고 해서 후보 6개가 모두 승인됐습니다. 새 아이콘 시작 화면 그림, 사주, 대표기도문, 타로, 첫이름 후기 창, 영어이름이며, 이날 차례로 진행됐습니다. 그록 주간 사용률은 아침 36%에서 저녁 59%가 됐고(11/23 초기화), 커서는 다른 모델 몫을 99% 썼습니다. 저녁에 새 후보 5개를 올려 선택을 기다립니다. 기도문·영어이름 결제 연결, 새 상품 4개의 실제 AI 품질 시험, 청첩장·퇴사 인사 같은 새 글방 상품, 운세 묶음 풀이권 3장, 무료 「오늘의 한 줄 운세」입니다. 낮에 대종님이 물은 세 가지에는 각각 의견을 냈고, 결정을 기다립니다. 묶음 할인은 「골라 쓰는 풀이권 3장」, 다른 풀이로 교환은 「교환 단추 대신 같은 값이면 아무 상품에나 쓰기」, 1,100원 받기는 「990원 유지」를 권했습니다.
- 커서 기본 모델: 오퍼스 몫을 99% 써서, 네 컴퓨터의 커서 기본 모델을 Grok 4.7 Extra High로 바꿨습니다. 이어 대종님 요청으로 한 번에 다루는 글 길이(문맥)를 500K로 늘렸습니다. 이때 Max 모드가 자동으로 켜져서, 사용 화면에서 추가 요금이 꺼진 계정인지 먼저 확인했습니다.
- 스킬 점검: 키 없이 돌아가는 외부 평가 도구로 클로드 스킬 전체를 1단계 점검하고 보고했습니다. 대종님이 별 쓸모없어 보인다고 해서 설치 파일과 결과를 휴지통으로 옮겼습니다. 점검에서 나온 진짜 문제는 고쳤습니다. 스킬 설명 속 꺾쇠 12곳과, 클로드가 명령 인자로 바꿔 버리는 본문의 $숫자 5줄입니다. 다시 생기지 않게 막는 시험을 더해 새벽 1시 6분에 합쳤습니다. 원래부터 실패하던 다른 시험 하나는 이번 변경과 상관없습니다. 다른 컴퓨터에는 각자 새 버전을 받을 때 반영됩니다.

## 아이패드 현황 화면

대종님이 거치대에 세워 두고 보는 아이패드 현황 화면 이야기입니다.
- 사용량 줄(취소): 처음에는 텔레그램 현황판에 그록·커서 사용량 줄을 넣으려 했습니다. 그런데 대종님이 보낸 사진 속 화면이 아이패드 현황 화면이어서, 그쪽에 같은 모양으로 넣는 게 맞다고 보고 개편 작업에 합쳤습니다. 브라우저로 커서 계정에 로그인해, 이제 한 곳에서 그록·커서 사용량을 모두 읽을 수 있습니다. 밤 9시 28분 측정값은 개편 작업으로 넘겼습니다. 그록 주간 28%(11/23 초기화), 커서 Ultra 1%·다른 모델 58%(12/17 초기화), 커서 Grok Bot 1%(11/24 초기화)였습니다. 이 항목은 끝난 것이 아니라 옮겨진 것입니다.
- 화면 검토: 늘 비어 있는 「내 차례」 칸과 다른 데서도 보이는 큰 시계가 가장 넓은 자리를 쓰고 있다는 의견이 나왔습니다. 정작 가장 자주 묻는 「지금 누가 뭘 하나」는 오른쪽 아래에서 잘립니다. 고칠 안은 이렇습니다. 시계는 머리줄의 작은 글자로 줄이고, 내 차례는 할 일이 있을 때만 커지는 띠로 바꿉니다. 왼쪽에는 지금 도는 일, 오른쪽에는 클로드와 그록·커서 사용 한도 표를 둡니다. 실제 아이패드에서 보이는 높이는 따로 확인이 필요하다고 적혔습니다.
- 개편(진행 중): 대종님이 「그 안대로 가」라고 해서 맡겼습니다. 첫 검수는 실제 자료 모양으로 화면이 넘치지 않는지 확인하라며 보류했습니다. 두 번째 검수를 통과해 새벽 1시 37분에 합치고 아이패드 화면에 반영했습니다. 그런데 그록 사용량 측정이 시간 초과로 멈춰서, 화면에는 값을 지어내지 않고 「못 읽음」으로 나옵니다. 멈춘 측정을 먼저 정상 종료시키고 몇 초 뒤 강제 종료하는 보완은 맞다고 봤지만, 원인이 측정 스크립트 쪽에 있어서 여기서 끝나지 않았습니다.
- 측정 멈춤 고치기: 측정 스크립트가 멈추는 원인과 남은 측정 세션 정리를 고쳐 오전 10시 33분에 합쳤습니다. 하지만 실제로 쓰는 사본에는 아직 반영되지 않았습니다(정리 안 된 변경이 남아 있음). 옛 코드가 남긴 측정 세션 하나도 그대로입니다. 반영하고, 실제 측정이 성공하고, 아이패드 실기기에서 확인한 뒤에야 개편을 닫습니다.

## 근무 녹음과 현장 도움

- 녹음 보고 카드와 클로드 제안: 근무 녹음 처리가 끝나면 단계별 보고 카드를 한 통 보내고, 하루 정리에 「클로드 제안」(만들어 볼 서비스·앱, 일 개선, 조언)을 붙이게 했습니다. 밤 9시 24분에 합쳤습니다. 그날 정리로 실제 제안을 만들어(만들어 볼 것 2, 일 개선 1, 조언 1) 위키에 붙였고, 보고 카드도 보냈습니다. 다음 녹음부터는 처리가 끝날 때마다 카드가 갑니다.
- 녹음기 시작 카드: 녹음기를 꽂아 파일을 가져오고 녹음기를 비우는 일이 끝나면 「녹음기 인식·이제 빼도 됨·받아쓰기 시작」 카드를 한 통 보내게 했습니다. 18시 48분에 합쳐졌습니다. 자동으로 합치지 말라는 표시가 빠져서 저장소가 먼저 자동으로 합쳤지만, 내용은 검증한 것과 같습니다. 이날 18시 37분 처리는 옛 코드로 돌았습니다. 다음에 녹음기를 꽂을 때 카드가 실제로 오는지 봅니다.
- 영어 접수 메모(진행 중): 근무 녹음 정리에서 나온 제안대로, 외국인 손님용 영어 접수 메모를 A4 한 장으로 만들었습니다. 호텔 바우처, 짐 개수(S/M/L), 손님 연락처, 담당자 이름, 마지막 확인 다섯 칸과 짧은 말 세 개가 들어 있습니다. 19시 18분 프린터로 한 부를 오류 없이 인쇄했고, 실물 확인은 대종님 몫입니다.

## 기기 정리와 기다리는 일

- 윈도우 PC 정리: 대종님 말대로 윈도우 PC에서 LED 스위치와 기가바이트 컨트롤 센터를 지웠습니다. 관리자 허용 창은 대종님이 눌렀습니다. 설치 목록, 실행 중인 프로그램, 예약 작업, 폴더에서 모두 사라진 것을 확인했습니다. 대종님이 말하지 않은 다른 조명 프로그램과 드라이버는 그대로 두었습니다.
- D200 절전·깜빡임(지켜보는 중): D200 버튼 패드의 자동 절전을 없애고, 직접 누르는 절전 버튼을 넣었습니다. 강제 절전은 밤 1~7시에만 하고, 승인·질문 답을 기다리는 컴퓨터의 키는 깜빡이게 했습니다. 아침 8시 3x분에 설치했고, 홈 화면에 「화면 절전」 버튼이 생긴 것을 확인했습니다. 대종님이 실제로 눌러 보는 것과 밤 강제 절전이 한 번 도는 것을 보고 닫습니다.
- 살아있음 위치정보 신고(보류): 살아있음이 위치기반서비스 신고 대상인지 묻는 건은 접수 처리 중입니다. 11/17 담당자와 통화해 주소 호수를 고치기로 했고, 결과 통지를 기다립니다.
- 말해줘 피드백(보류): 아이폰판은 11/9에 접었고, 안드로이드 1.0.1이 플레이에 공개돼 있습니다. 남은 두 건이 1.0.1에 들어갔는지 코드를 대조하는 일이 남았습니다. 「말하기」를 누를 때 키보드 닫기, 키보드가 메뉴를 가리는 문제입니다.
- 인터넷 개인정보 정리(보류): 사업 관련 정보는 남기고 나머지를 지우는 일입니다. 11/13 앱 배포 사이트의 개발자 계정과 메모요 소유 확인 단계에서 멈춰 있고, 이어서 볼 예정입니다.
- 살아있음 링크 연결(보류): 서버 데이터를 읽기만 해서 확인해 보니, 함께 쓰는 상대의 마지막 확인은 11/14이고 그 뒤 안 읽은 메시지가 6건입니다. 상대는 이름·번호를 먼저 묻도록 바꾼 새 판을 아직 보지 못한 것으로 보입니다. 서버에 앱 버전 기록이 없어서 이 부분은 추정입니다. 상대가 새 판에서 이름·번호를 적어야 대종님 폰에 제대로 표시되는지 확인할 수 있습니다.

## 아직 남은 일

가장 먼저 기다리는 것은 바깥 심사입니다. 새 한 글자 아이콘을 단 앱들은 앱스토어 심사와 플레이 검토 결과가 아직 나오지 않았습니다. 모여요는 구글 검토를 통과하면 바로 공개됩니다. 모여요 토스 로고는 검토가 3~7영업일 걸리고 그동안 고칠 수 없어서 임시저장만 해 두었고, 언제 요청할지는 대종님이 정합니다. 할일요는 덜 끝난 드라이브 로그인 기능 때문에 멈춰 있습니다. 시작 화면 그림과 새 스토어 스크린샷 44장은 다음 판에 싣습니다(11/25 다시 확인). 새 아이콘이 대종님 아이폰에 깔리면 홈 화면 한쪽에 대종님 앱을 모으는 일도 남았습니다. 새로 만든 묶음 출시 도구는 다음 묶음 출시 때 처음 실제로 씁니다.

운세 앱과 글방은 코드로는 사주·타로·기도문·영어이름·축사 결제까지 준비가 끝났습니다. 하지만 손님이 실제로 살 수 있으려면 결제 상품 번호 등록, 실제 AI 품질 시험(유료 사용 승인 필요), 처리방침 문장 확정, 토스 검토 요청이 남았고, 모두 대종님 승인이 필요합니다. 결정을 기다리는 일도 있습니다. 기도 제목·아이 이름처럼 민감한 입력을 받는 근거와 동의 문구, 콘솔 소개 글 두 줄, 묶음 풀이권과 값(990원 유지 여부)입니다. 토정비결 새 판은 토스 검토 중이라, 승인되면 출시하고 프로모션을 다시 시작할지 묻습니다. 첫이름 구매자 후기 창은 네 개 하위 작업을 등록만 한 상태입니다. 앱스토어 링크 출처 집계는 11/24에 처음 봅니다. 스레드 후속 기록은 세 번째 모르는 손님 결제가 생기면 한 번에 올리고, 11/21에 다시 봅니다.

알림 쪽에서는 보조 폰 카카오톡 알림이 대종님 폰에 실제로 도착하는지 봐야 합니다. 30분 문자·60분 전화 단계를 브릿지에 실제로 올린 뒤 끝까지 동작하는지도 남았습니다. 확인할 때는 실제 일이 걸린 카드 대신, 아무 결정도 걸려 있지 않은 시험용 질문 카드 하나를 30분 그대로 두고 카톡이 오는지 보면 부담이 없습니다. 승인 전화도 첫 실제 카드에서 다시 봅니다(11/20). 좁은 화면에서 질문 카드를 못 읽는 문제가 다시 생긴 건은 막 손대기 시작했습니다. 아이패드 현황 화면의 한도 표는 고친 측정 스크립트를 실제 쓰는 사본에 반영하고, 측정 성공과 기기 확인을 거쳐야 끝납니다. 맥 화면 조작 도구는 세 묶음의 고침이 끝났고, 실제 화면 확인 항목과 마지막 단계가 남았습니다. 클로드 주간 85% 알림은 설치가 끝났다는 기록과 설치 작업이 아직 열려 있다는 기록이 함께 있어서, 첫 판정 기록을 직접 확인해야 합니다. 텔레그램 현황판의 1시간 새 글 기능도 첫 실가동 결과를 봐야 합니다.

그 밖에 확인할 일이 있습니다. D200 절전 버튼과 밤 강제 절전(11/19), 녹음기 시작 카드(다음에 꽂을 때, 11/19), 승인 앱 1번 아이콘 재설치, 영어 접수 메모 실물, 쿠팡 파트너스 35번 원고에 대한 수정 답입니다. 기다리는 일도 있습니다. 위치정보 신고 결과(11/21), 말해줘 안드로이드판 코드 대조(11/20), 인터넷 개인정보 정리(11/19), 살아있음 링크 연결 상대의 새 판 사용(11/21)입니다. 그록 사용률은 저녁 59%로 90% 목표에 못 미쳐서, 저녁에 올린 새 후보 다섯 개 가운데 대종님이 무엇을 고를지 기다립니다.
